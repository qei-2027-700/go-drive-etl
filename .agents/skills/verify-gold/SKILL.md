# Gold・Drive CSV・画面の検証

リポジトリルートで実行する。読込だけではクラウド処理を開始しない。

1. `.env.example` と [実行手順](../../../docs/gold-verification.md) で設定・認証・成果物の扱いを確認する。`.env` を `source`、`eval` しない。値や実データをチャットへ貼らない。
2. 現状確認の依頼では `go run ./cmd/verify_gold` を使う。再集計・CSV再出力を依頼されている場合は `go run ./cmd/verify_gold --refresh-and-export` を使う。後者は既存Goldテーブルを置換し、指定DriveフォルダのCSVを2回更新する。依頼が読取のみなら実行しない。途中失敗したら停止し、原因を解消するまで書込を繰り返さない。
3. JSONの段階別結果を読む。SQL差分、行数・列数、重複、2回目のID維持を確認する。`--allow-empty` は対象Silverが空であることを意図した依頼に限る。空でないSilverに対する空Goldは常に失敗する。
4. ログイン済みブラウザが使える場合、設定の `GOLD_DASHBOARD_URL`、未設定なら `docs/looker-studio.md` のレポートを開く。接続エラーの有無、全期間のスコアカードとログの期待値、日次チャートと最新文書表を確認する。API成功だけで画面を確認済みにしない。ログイン要求では認証を迂回せず未確認とし、URLと期待値を人へ示す。
5. 実行日時、各段階の結果、画面の確認根拠または未確認理由、ログ保存先を報告する。書込モードの全検証と画面確認が成功した場合のみ全体成功。SQL/CSVの失敗は失敗、画面未確認や再出力未実施は一部未確認とする。実データ、文書ID、出典URL、秘密は公開ログやIssueへ転記しない。
